# Developer notes

Technical notes, design decisions and the pitfalls we ran into while building this. Read this before changing something big.

## Architecture

```
~/.config/tahoe/settings.json     single source of truth (written by the Settings app)
        │  tahoe-settings --apply
        ├─► ~/.config/hypr/tahoe.lua      monitors, input, rounding/blur/opacity, animations, VRR
        ├─► ~/.config/hypr/hypridle.conf  lock / screen-off / suspend timers
        ├─► ~/.config/tahoe/clock.fmt     read by tahoe-clock (waybar clock)
        └─► apply_theme(): ~/.themes/Tahoe/*, ~/.config/gtk-4.0/gtk.css, waybar/style.css,
                           nwg-dock-hyprland/style.css, swaync/style.css, rofi *.rasi colors
```

- `config/hypr/hyprland.lua` is the *static* config; it does `require("tahoe")` for everything generated.
- `tahoe-settings` is one Python file (GTK4 + libadwaita). Modes: default (Settings window), `--pane <key>`, `--control-center`, `--apply`, `--apply-theme`, `--default-wallpaper`.
- The GTK theme is generated from `share/tahoe/base.css` (dark). Light mode is derived by string substitution in `gtk_css()`; bar/dock/menus are generated from templates in `apply_theme()` with a small palette dict.
- Window classes `org.tahoe.Settings` / `org.tahoe.ControlCenter` are matched by window rules in `hyprland.lua` (floating, size, position).
- `tahoe-firstrun` runs once on the first Hyprland start (marker `~/.config/tahoe/.firstrun-done`) because the installer usually runs *outside* Hyprland and cannot see the monitors.
- The settings code only starts/kills processes (`waybar`, `hypridle`, dock) or calls `hyprctl`/`gsettings` when `HYPRLAND_INSTANCE_SIGNATURE` is set (`IN_HYPR`). Otherwise the installer would disturb a KDE/GNOME session.

## Menus without a menu bar protocol

The Apple menu, app menu, Recent Items and Force Quit are rofi `-dmenu` lists with an `apple.rasi` theme (dropdown at the top-left). Separators are rows with `\0nonselectable\x1ftrue`. Shortcuts are right-hand `<span alpha>` hints (`-markup-rows`).

## Pitfalls (save yourself the time)

1. **Hyprland ≥ 0.55 uses a Lua config.** `hyprland.conf` is ignored/invalid; defaults live in `/usr/share/hypr/hyprland.lua`. Dispatchers are Lua too: `hyprctl dispatch 'hl.dsp.exit()'`, `'hl.dsp.dpms({ action = "off" })'`, `'hl.dsp.focus({ workspace = 2 })'`. `hyprctl reload` works; check `hyprctl configerrors`.
2. **Editing `hyprland.lua` triggers an automatic reload.** If it `require`s a file that does not exist yet, monitors silently fall back to defaults. Create `tahoe.lua` first.
3. **hyprlang (hyprlock/hypridle/hyprpaper configs) needs one option per line.** `block { a = 1; b = 2 }` on a single line parses as garbage → hyprlock shows a *black screen*. Use proper multi-line blocks and absolute paths.
4. **Nerd-font/Font Awesome glyphs in JSON:** write them as `` escapes. Pasting the raw private-use glyph through some tools silently produces an empty string (the Apple logo vanished once). Surrogate pairs (`\udb80…`) from memory were wrong; stick to Font Awesome BMP code points.
5. **GTK3 CSS (waybar) has no `filter:` property** → parser warnings. Don't use CSS filters in the theme.
6. **`AQ_DRM_DEVICES` and `by-path` names:** by-path names contain `:` which is the list separator. Resolve with `readlink -f` first. Card numbers may change between boots, so the repo does not pin them.
7. **nmcli `-t` escapes `:` as `\:`.** Split with `re.split(r'(?<!\\):', line)`.
8. **Never kill your own shell.** `pgrep -f`/`pkill -f` patterns can match the parent `sh -c "…"` that launched you (the Control Center "toggle if already open" logic did exactly that). We scan `/proc/*/cmdline` for an exact `python* … tahoe-settings … --control-center` match instead.
9. **Blur only shows through translucent surfaces.** `decoration.blur` is on; for layer surfaces (waybar, rofi, swaync, dock) we add `hl.layer_rule({ match = { namespace = … }, blur = true, ignore_alpha = 0.2 })`. Window backgrounds in the theme are ~0.85–0.94 alpha so text behind does not bleed through.
10. **Hyprland (like KWin) holds the dGPU for the whole session** — dynamic GPU passthrough/unbinding to a VM cannot work from inside a running compositor; use a separate session/mode.
11. **libadwaita ignores GTK themes.** Overrides go in `~/.config/gtk-4.0/gtk.css` (the app regenerates it), using libadwaita named colors (`@define-color accent_bg_color …`).
12. **Symbolic icons:** `breeze-dark` lacks some symbolic names; the Settings app forces `Adwaita` as its icon theme.
13. **rofi ≥ 2.0 renamed `modi` → `modes`** (list syntax: `modes: [drun, run];`). With the old key and several options on one line the whole line is swallowed and Spotlight opens with an error box. Write `configuration { … }` multi-line. Also override *every* element state (`normal/alternate/selected × normal/urgent/active`) or the default theme's cream backgrounds leak through.
14. **Settings must be single-instance.** Waybar items launch `tahoe-settings --pane X`; with `NON_UNIQUE` every click opened a new window. The app now uses `HANDLES_COMMAND_LINE` and switches the pane of the existing window. The Control Center stays `NON_UNIQUE` (it toggles by killing an existing instance).
15. **Waybar hover boxes:** give modules `margin: 3px 1px; border-radius: 6px` so the highlight is inset like macOS; full-height hover looks wrong. `hyprctl` synthetic cursor moves do not trigger waybar hover — to inspect geometry, temporarily set a background on the modules.
16. **Waybar `custom/*` modules never get a `:hover` state** (the hand cursor appears, but no CSS node is hovered), while native modules (`network`, `pulseaudio`, `battery`, `clock`, `hyprland/*`) do. Static buttons (Apple logo, search, Control Center, notifications) are therefore defined as native `clock#<name>` modules with a fixed icon `format` — CSS ids become `#clock.apple`, `#clock.spotlight`, … The real clock is `clock#time`.
17. **Turkish/localized dates in the native clock need the `L` modifier**: `"format": "{:L%a %e %b  %H:%M}"` plus `"locale": "tr_TR.utf8"`. Without `L` it stays English.
18. **Icon glyph centering:** Nerd Font (non-Mono) glyphs are wider than their advance and overflow to the right of the hover box. Use the *Mono* family (`JetBrainsMono NFM`) for icon-only modules and a bigger `font-size` to compensate; for text+icon (battery) wrap the icon in `<span font='JetBrainsMono NFM 12'>`. Keep the bar `height` ≥ the modules' minimum (waybar warns otherwise).
19. **GTK3 CSS (waybar) rejects `filter:` and `-gtk-icon-size`.** The theme generator strips `-gtk-icon-size` from the GTK3 file.
20. **Window-rule `move` + `size` must use the window's real size.** The Control Center rule said `size 360 480` but GTK needed 361×520; Hyprland positioned it for 480 and the window then grew from the centre, ending 20 px *higher* — under the 37 px bar. Match the rule size to the real size (`361 520`) and anchor with `monitor_w-369 44` (just below the bar). Also avoid `no_anim` on translucent blurred windows if you see leftover frames on close.
21. **Control Center switching.** Clicking another bar icon first steals focus (→ the panel would close) and *then* spawns a second `tahoe-settings --control-center --from <icon>`. The panel therefore delays its focus-loss close by 900 ms; the second instance does not kill it but sends `SIGUSR1` (label in `$XDG_RUNTIME_DIR/tahoe-cc.req`): a different label keeps it open, the same label closes it (toggle).
22. **Tray items:** the visible node is the `image`, not the container. Style `#tray image` (margin/padding/radius) and hover via `#tray image:hover`; styling `#tray > *` leaves a full-height hover box.
23. **Control Center is a layer-shell popup** (`gtk4-layer-shell`), not a floating window: anchored top-right just under the bar, `OVERLAY` layer, `EXCLUSIVE` keyboard (so `Esc` closes it). Behind it, one near-transparent **click-catcher** layer surface per monitor (anchored to all edges, top margin = bar height so bar icons stay clickable) closes it on any outside click. Hovering away never closes it. Gotchas: (a) the Python binding needs `LD_PRELOAD=libgtk4-layer-shell.so` — the script re-execs itself; (b) a *fully* transparent surface is never mapped, use `rgba(0,0,0,0.01)`; (c) `follow_mouse = 2` does NOT keep keyboard focus off a hovered window in Hyprland, so focus-loss based closing is unreliable. Blur comes from `hl.layer_rule` for namespace `tahoe-cc`.
24. **Tray apps that ignore left click** (Claude Desktop only handles the *Show* item in its dbusmenu): `tahoe-tray-assist` watches `StatusNotifierItem.Activate` calls with `dbus-monitor` and clicks the menu item whose label matches `göster|show|open|aç` for apps listed in `~/.config/tahoe/tray-activate.json` (`{"apps": ["Claude"]}`).
25. Hyprland ≥ 0.55: `hyprctl keyword` no longer works; use `hyprctl eval '<lua>'` (e.g. `hl.config({ input = { follow_mouse = 1 } })`) to change options at runtime.
28. **Control Center Wi-Fi row opens a network list** (a `Gtk.Stack` page with back arrow, on/off switch, list, inline password field, "Wi-Fi Ayarları…"). The scan (`nmcli dev wifi rescan`) is started only when that page is opened (or Wi-Fi is switched on); everywhere else networks are read from NetworkManager's cache with `--rescan no`. The panel resets to the main page every time it is shown.
29. **Bluetooth row** works the same way (`stack` page `bt`): list from `bluetoothctl devices` + parallel `bluetoothctl info <mac>` (alias, icon, paired, connected), icons from BlueZ's `Icon` field, click = connect / disconnect / pair+trust+connect. `bluetoothctl --timeout 9 scan on` runs only when the page is opened or Bluetooth is switched on. BlueZ forgets unpaired devices after a few minutes, so an empty list when nothing is nearby is normal; devices whose name is just a MAC address are hidden.
30. **Layer-surface blur does not work for `hl.layer_rule` here** (tried `blur`, `ignore_alpha`, `xray`, `enabled`, `order`, namespaces; window blur works fine). The Control Center therefore fakes frosted glass: the daemon pre-blurs the wallpaper (`GaussianBlur(26)` + saturation 1.7) per monitor, crops the region under the panel (top-right) into `$XDG_RUNTIME_DIR/tahoe-cc-bg-*.png` on every show and applies it as a CSS `background-image` with a tint gradient (`.tahoe-cc-box.cc-m<N>`). Windows beneath the panel do not show through (they would in real macOS), but nothing bleeds either. Use a fresh file name per show — GTK caches CSS images by URL.
31. **macOS metrics** (from a Big Sur screenshot, 1 pt ≈ 1 px): panel 296 wide, padding 10, card radius 12, gaps 10, connectivity rows 38 px (card 134), DND 62, small tiles 62×62, slider cards 61 (title 13, pill **21 px**, thumb diameter = pill height, round button 25), now-playing 61 with 42 px art. `PillSlider` draws the thumb with `d = widget height` (a fixed 28 px thumb in a taller widget looked "too small").
32. **Own icon font for the bar.** No Nerd Font glyph looks like macOS' Control Center icon (two stacked toggles) or a thin-outline battery, so `tools/make-icon-font.py` (fontTools) draws `TahoeIcons.ttf`: U+E900 control center, U+E901…E905 battery at 0/25/50/75/100 % (waybar `format-icons`). The installer generates it into `~/.local/share/fonts` (needs `python-fonttools`). Charging is shown by colour (`#battery.charging`, green), not by a bolt glyph. The battery percentage lives in the tooltip (`tooltip-format-*`, Turkish texts).
33. **Vertical alignment of bar icons is measured, not guessed.** Icons come from different fonts (TahoeIcons, JetBrainsMono NFM, Inter, tray), so their ink centers differ by a few pixels. Capture the bar with `grim`, threshold the bright pixels per column group and compare each group's vertical centre with the bar centre (physical px; bar 37 logical × 1.25 ≈ 46). Fix by shifting glyph outlines in `tools/make-icon-font.py` (`CC_DY`, `BAT_DY`, font units) — CSS cannot translate text. Restart waybar after regenerating the font (fontconfig cache).
34. **rofi hover + click:** `hover-select: true` is a *configuration* option (a `listview { hover-select: … }` theme property is accepted but does nothing); without it, single-click activation leaves no way to navigate by mouse. **rofi mouse activation:** by default a click only *selects* (`me-select-entry: MousePrimary`) and a double click accepts (`me-accept-entry: MouseDPrimary`). For macOS-style menus we set `me-select-entry: "MouseSecondary"` (right click) and `me-accept-entry: "MousePrimary"` in both `config.rasi` and `apple.rasi`. An *empty* binding (`""`) is rejected, and — again — every `configuration { … }` option must be on its own line or rofi mis-parses the line and shows an error box.
35. **Mission Control** (`MissionControl` window + `mc_collect()` in `tahoe-settings`, triggered with `tahoe-cc mission`): a full-screen layer-shell overlay per monitor with a blurred/darkened wallpaper (same `wall_blur()` as the Control Center glass). Real screenshots only exist for the **active** workspace — Hyprland does not keep hidden workspaces rendered and `grim` cannot capture them — so other desktops show a window-layout sketch and cards with the app icon. Data comes straight from Hyprland's IPC socket (`hypr_json()`, ~1 ms) instead of spawning `hyprctl` (~50 ms each inside a big Python process); the screenshot is a `grim … -t jpeg` taken *before* the overlay is shown. `Gio.DesktopAppInfo.search` is slow → cached per window class. Open latency ≈ 140 ms.
36. **Silent `str.replace` failures bite.** A patch that did `s.replace(old, new)` without `assert old in s` skipped `hide()`, so the toggle shortcut re-opened instead of closing Mission Control. Always assert when patching generated/edited source.
37. **Monitor offsets change when the external monitor is unplugged** (the laptop panel moves from x=2560 to x=0 after a reload), so hard-coded global pointer coordinates in tests go stale — read `hyprctl monitors` first.
38. **Wallpapers are real photos now** (`share/wallpapers/*.jpg`, 2560×1440, CC0 from Wikimedia Commons — license verified per file via the API's `LicenseShortName`; Wikimedia rate-limits (HTTP 429) so batch the API query and back off). The installer copies them to `~/.local/share/tahoe/walls/`; `tahoe-settings --default-wallpaper` converts the first one to `~/.config/hypr/wallpaper.png` **only if none exists** (a reinstall never overwrites the user's choice). hyprpaper/hyprlock need a PNG-named file, so `save_wall()` re-encodes JPEGs. The Control Center glass, Mission Control and the lock screen all derive from this file, so a photo makes them look far better than the old gradients.
39. **Login screen (Plasma Login Manager 6.8, `plasmalogin`)**: config lives in `/etc/plasmalogin.conf` (`[Greeter] WallpaperPluginId=…`); the greeter runs as user `plasmalogin` (home `/var/lib/plasmalogin`) and does **not** read the user's home or look-and-feel, so a custom QML theme needs root-installed files under `/usr/share` and cannot be tested without logging out — a broken greeter can lock you out of the GUI. We therefore only install the photos as standard KDE wallpaper packages (`tools/install-login-wallpapers.sh`, `/usr/share/wallpapers/Tahoe-*`) so the supported KCM (System Settings → Login Screen) can pick them. ArchWiki is behind an Anubis block for non-browsers; KDE/CachyOS forum threads were the usable source.
40. **Login manager = greetd + our own greeter** (`bin/tahoe-greeter`, `tools/install-login-theme.sh`). Why: Plasma Login Manager can't be themed beyond a wallpaper and its greeter ignores user settings; ReGreet's layout is fixed (card + User/Session rows) so the macOS layout is impossible with CSS only. The greetd protocol is a tiny stable JSON-over-UNIX-socket (4-byte native-endian length + JSON: `create_session` → `auth_message` → `post_auth_message_response` → `start_session`), so the greeter is ~250 lines and can be swapped for any other greetd greeter by editing one line in `/etc/greetd/config.toml`. Tested without root: `tahoe-greeter --demo` (password `pass`), a fake greetd server (wrong/right password, `start_session` cmd), and nested `cage -s -- tahoe-greeter --demo`. **Not tested**: real greetd+PAM login and the real VT (needs a reboot).
41. Greeter pitfalls: (a) ReGreet/greeter CSS at APPLICATION priority is overridden by the user's `~/.config/gtk-4.0/gtk.css` (USER priority) — only matters in demo; the real greeter runs as user `greeter`. (b) pin `gtk-icon-theme-name` to Adwaita in code (user themes lack e.g. `battery-level-*`); Adwaita has `battery-level-100-charged-symbolic`, not `…-100-charging-…`. (c) pick the network icon only from physical interfaces (skip `veth*`, `docker*`, `br-*`, `virbr*`) or a docker bridge looks like "wired". (d) hide the `uwsm` session when `uwsm` isn't installed. (e) GTK has no real blur → use a pre-blurred background if you want a glass card (we use the unblurred photo like macOS).
42. Safety of the switch: `install-login-theme.sh` runs `systemctl enable -f greetd.service` (no `--now`, so the running session is untouched), saves the previous display-manager unit in `/etc/greetd/tahoe-prev-dm`, backs up `/etc/greetd/config.toml`, installs `/usr/local/sbin/tahoe-login-restore`. Test it with `ROOT=/tmp/fake NO_SYSTEMCTL=1 NO_PACMAN=1`.
43. **Lock screen (hyprlock) now mirrors the login layout**: unblurred photo, date + huge tinted clock at the top, round avatar + name + password pill at the bottom (`config/hypr/hyprlock.conf.tpl`, avatar from `tools/make-avatar.py` → `~/.cache/tahoe/avatar.png`, uses `~/.face` if present). Pitfalls: hyprlock sizes are physical pixels (looks small on 2560 wide → scale up); `font_family = "Inter Bold"` etc. do **not** select a weight with a variable Inter — use Pango markup `<span font_weight="700">$TIME</span>` in the label text. Test safely: run `hyprlock` in the background, `grim`, then `pkill -USR1 -x hyprlock` (unlocks).
44. **greetd sessions don't have `~/.local/bin` in PATH** (the old login manager did, via its profile handling). Symptom after switching: Control Center, dock, tray-assist didn't start and bar clicks (`tahoe-cc …`) did nothing, while `/usr/bin` programs (waybar, hyprpaper…) worked. `hl.env("PATH", …)` in `hyprland.lua` did **not** reach `hl.exec_cmd` children, so every launch of a `tahoe-*` command (and waybar, whose clicks inherit PATH) goes through `P = "env PATH=…/.local/bin:… "`. Don't rely on login-manager environment; set it explicitly in the compositor config. Also set `ecosystem = { no_update_news = true }` to avoid the post-update popup.
45. **Mission Control drag & drop**: window cards are `Gtk.DragSource`s (payload = window address string), desktop thumbnails and the `+` button are `Gtk.DropTarget`s. Drop → `hl.dsp.window.move({ workspace = N, follow = false, window = "address:0x…" })` (`follow = false` keeps the current desktop; dropping on `+` creates desktop max+1), then the view refreshes **without** a new `grim` shot (a new shot would capture the overlay itself). Careful when probing dispatchers: `hl.dsp.window.move({ workspace = 3 })` without `window =` moves the *focused* window. Tested with `tools/vdrag.py` (virtual mouse press/move/release through `/dev/uinput`) on a throw-away kitty window.
46. **Mission Control: swap windows** — dropping a card on another card runs `hl.dsp.window.swap({ window = "address:A", target = "address:B" })` (accepted keys: direction, target/with/other, next, prev). Cards are sorted by on-screen position `(y, x)` so the order follows the real layout after a swap. The active desktop's cards are cropped from the single `grim` shot taken when Mission Control opened, so the original positions are kept in `pos0` (address → (at, size)); otherwise after a swap each card would show the *other* window's picture. GTK notes: `Gtk.DragSource` has no `get_start_point`; use the `prepare` x/y; the drag icon must be a *static* snapshot (`WidgetPaintable.get_current_image()`) if the source card is hidden during the drag; the icon hotspot is ignored under Hyprland (icon hangs at the cursor's bottom-right).
47. **Menu bar and Apple/App menus moved from Waybar+rofi to Quickshell** (`config/quickshell`, installed to `~/.config/quickshell/tahoe`, started with `qs -c tahoe`; Waybar stays as fallback when `qs` is missing). Why: Waybar custom modules can't hover/click like real buttons, and rofi `-dmenu` can't do submenus, right-aligned shortcuts or a non-pre-selected first row. Structure: `Theme` (colors, read live from `~/.config/tahoe/bar-theme.json` which tahoe-settings writes → dark/light + accent still work), `Sys` (active window, nmcli state, recent items), `Bar` (one per screen), `BarButton` (per-element hover + delayed tooltip), `MenuList`/`MenuPopup` (drop-down + one submenu level).
48. Quickshell pitfalls: (a) a `qmldir` in the config dir **hides every type not listed in it** — list all components (`Bar 1.0 Bar.qml`…) or you get "Bar is not a type"; (b) the process name is `qs`, so `pkill -x quickshell` kills nothing; (c) `PopupWindow` is an xdg_popup → no compositor blur (use a more opaque `menuBg`) and **no keyboard focus**: make the bar `focusable` while a menu is open and route `Keys.onPressed` from the bar to the menu (`HyprlandFocusGrab` with bar + popups in `windows` handles click-outside); (d) a popup's items get no hover tooltips for free — `BarButton` has its own; (e) font metrics differ from GTK: icons needed per-element `yOffset`s (measured with grim: compare bounding boxes of bright pixels in both bars, see `/tmp` scripts in the commit message history); (f) the editing tool stored glyph escapes like `\uF179` as raw private-use characters in the QML files — fine, but match on neighbouring text when patching; (g) `Hyprland.dispatch()` is not used: menu actions run `hyprctl dispatch 'hl.dsp…'` with an explicit `window = "address:…"` captured from `Sys.activeAddress` (a popup grab can change the focused window).
49. **Not verified**: `Pencereyi Kapat` and `…Uygulamasından Çık` from the app menu (testing them was blocked by the auto-mode safety classifier; `hl.dsp.window.close({ window = … })` returned "ok" but did not close a kitty window, so the menu focuses the window first and uses plain `hl.dsp.window.close()`), tray icons (no tray app was running), external-monitor layout (one bar per screen via `Variants`, only one screen was available).
50. **Settings opened 4–6 s late** because the General pane ran `lspci | grep VGA` while building the window: `lspci` reads PCI config space and wakes the runtime-suspended NVIDIA dGPU (0.9–2.2 s of system time), blocking the GTK main thread before the first frame. Fix: `gpu_names()` reads `/sys/bus/pci/devices/*/{class,vendor,device}` (cached by the kernel, doesn't wake the card) and resolves names from `pci.ids` (~9 ms). General rule: never run PCI/GPU-touching tools (`lspci`, `nvidia-smi`, `glxinfo`) on the UI thread of anything on a hybrid laptop; profile with a wrapper that monkey-patches `sh()` and logs thread + duration. Window now shows fully rendered at ~0.6 s; no other pane had a >0.15 s main-thread command.
51. **Second cause of the slow Settings start: GTK4's default renderer wakes the NVIDIA dGPU.** With the card runtime-suspended, launching any GTK4 window made `/sys/bus/pci/devices/0000:01:00.0/power/runtime_status` go `suspended → resuming (1.3 s) → active (2.2 s)` and the window appeared at ~2.3 s (also costs battery). Measured with `GSK_RENDERER`: default 2.29 s + wakes the card; `cairo` 0.33 s (software); `ngl` 0.6 s and the card stays suspended; `GDK_DEBUG=vulkan-disable` and forcing Mesa-only EGL did **not** help. Fix: `os.environ.setdefault('GSK_RENDERER', 'ngl')` before GTK initializes in `tahoe-settings` (also covers the Control Center / Mission Control daemon) and `tahoe-greeter` (the login screen woke the dGPU at every boot). Test recipe: poll `runtime_status` while launching the app (`tools`-style script in the session history), and wait for `suspended` between runs.
52. **Blur behind Quickshell menus/tooltips (Hyprland 0.57.2)**: `decoration:blur:popups = true` (+ `popups_ignorealpha`) did **not** blur anything here (measured: Laplacian edge energy behind a translucent popup 17.57 on and off). The per-layer rule does: `hl.layer_rule({ match = { namespace = "tahoe-bar" }, blur_popups = true, ignore_alpha = 0.2 })` — the menus are xdg_popups of the bar's layer surface, so the bar's namespace rule blurs them (energy 17.57 → 4.46); no layer-shell rewrite needed. Wiki: wiki.hypr.land/0.57.0/configuring/core/rules/layer-rules/ (the old `Configuring/Variables` URLs 404 now; layerrule syntax is Lua `hl.layer_rule` since 0.55). With blur working `Theme.menuAlpha` is 0.68 (0.62 and 0.85 looked too see-through **without** blur). Testing without hijacking the user's pointer: `qs -c tahoe ipc call bar menu apple|app|close` (IpcHandler in `Bar.qml`), and a throw-away `qs -p <dir>` test panel for rule experiments (`hyprctl reload` clears rules added with `hyprctl eval`).
53. **Battery icon is drawn in QML** (`BatteryIcon.qml`, ≈25×11 px): rounded outline, nub, fill ∝ level, green + bolt (Canvas) while charging, red below 20 %. Measured in the bar: 31×12 physical px, vertical centre 22.5 (wifi 22.0, control centre 22.5, search 22.0).
54. **Control Center's "square blur layer" was a clipped CSS box-shadow, not Hyprland blur.** `.tahoe-cc-box` (radius 18 px) had `box-shadow: 0 14px 40px rgba(0,0,0,.45)`, but a layer-shell surface can't draw outside its own rectangle, so the shadow was cut off at the surface edge and showed as a dark square-cornered patch outside the rounded corners. Ruled out Hyprland first: layer rule `blur = false`, `ignore_alpha` 0.6 and 0.2 gave pixel-identical results. Fix: `box-shadow: none`. To keep a shadow you'd need a transparent margin ≥ the blur radius around the box inside the surface. Tip: to find out *which* layer draws a visual artefact, toggle one suspect at a time and compare magnified crops (`magick -crop … -scale 800%`) rather than guessing; `hyprctl reload` clears rules added with `hyprctl eval`.
55. **Settings app restructured to follow Apple's System Settings (macOS Tahoe 26) help pages** (support.apple.com/guide/mac-help …; Wi-Fi `mh11935`, Battery `mchlfc3b7879`, Desktop & Dock `mchlp1119`, Lock Screen `mh11784`, Appearance `mchlp1225`, Displays `mh40768`, Sound `mchl9777ee30`, Notifications `mchl205da693`, Keyboard `kbdm162`, Users & Groups `mtusr001`, Privacy & Security `mchl211c911f`, Accessibility `mh35884`; Apple's index pages don't list the sidebar in one place, and the page text came through a summarizing fetch tool, so treat labels as "Apple's English structure, our Turkish wording"). ## Testing

- `./install.sh --dry-run` prints actions only.
- Sandbox install (does not touch your real config):
  `env -u HYPRLAND_INSTANCE_SIGNATURE HOME=$(mktemp -d) ./install.sh --no-packages --yes`
  then `Hyprland --verify-config -c "$HOME/.config/hypr/hyprland.lua"` (with that HOME).
  **Unset `HYPRLAND_INSTANCE_SIGNATURE`** or the sandbox run would kill/restart your real waybar/dock.
- Build every Settings pane headlessly (catches exceptions): import the file with `SourceFileLoader`, create `TahoeApp('settings', None)` and call each `PANES[i][3]()` inside an `activate` handler.
- **Real hover/pointer testing:** `tools/vmouse.py x,y …` creates a virtual relative mouse through `/dev/uinput` (needs write access, e.g. an ACL for your user) and moves the pointer to global logical coordinates with real motion events (`SHOT=/path/hv_%.png` takes a screenshot at each stop; `CLICK=1` sends a left click at each stop). `hyprctl dispatch 'hl.dsp.cursor.move(…)'` moves the cursor but does **not** trigger hover in layer surfaces like waybar.
- Screenshots: `grim -o <output> out.png` on an empty workspace so no private content is captured; crop with ImageMagick.
